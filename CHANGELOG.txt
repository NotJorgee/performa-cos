UPDATE NOTES: 2026-11-19
One-Touch GPS Attendance, DAR Clock-In Gating, & Sub-Second Predictive AI
================================================================================

SUMMARY FOR MOBILE & APP DEVELOPERS
-----------------------------------
1. One-Touch Integrated GPS on Clock Buttons:
   - Removed the separate Real-Time GPS Status Bar and manual "Refresh GPS" button
     to provide a cleaner, more intuitive user interface.
   - GPS satellite acquisition is now seamlessly integrated into the "Clock In"
     and "Clock Out" action buttons.
   - When tapped, the button displays real-time progress:
     "Acquiring GPS..." (locks satellite signal) -> "Recording Punch..." -> "Timed In / Out".
   - Uses high-accuracy device geolocation with a 6-second satellite lock window
     and immediate lock when precision reaches <= 25 meters.

2. Daily Accomplishment Report (DAR) Attendance Gate:
   - In accordance with EVSU-Ormoc institutional policy and CSC Form 48 standards,
     employees must now record their shift Clock-In (or have an approved Official
     Business / OB slip) before accessing the Daily Accomplishment Report.
   - If an employee navigates to DAR without clocking in, a dedicated gate card
     is displayed informing them of the requirement, with direct action buttons:
     "Proceed to Attendance & Clock In" and "File Official Business (OB) Slip".
   - Backend API (backend/app/routers/dar.py) also strictly enforces this check
     on POST /api/dar, rejecting unclocked submissions with HTTP 403 Forbidden.

3. Sub-Second Predictive AI Autocomplete:
   - Ghost-text completion latency reduced from 3-5 seconds down to ~0.9 seconds.
   - Re-ordered candidate AI models in backend/app/ai_service.py to place
     "gemini-3.1-flash-lite" first, bypassing the non-responsive "gemini-3.5-flash-lite".
   - Reduced frontend textarea debounce from 350ms to 200ms for immediate feedback.
   - Set backend AI model execution timeout to 2.0s.

4. DAR Multi-Campus Polygon Geofence Tolerance Buffer:
   - DAR backend verification now checks polygon perimeter boundaries with a 50-meter
     tolerance buffer, preventing false out-of-bounds rejections on campus perimeters.

5. Attendance System Rules: Out-of-Bounds & Forgotten Clock-Out Specifications:
   - Out-of-Bounds Punch: If an employee attempts to clock in/out outside campus,
     the system rejects the punch, reports the exact distance to the nearest campus
     boundary (e.g. "You are 120m away from EVSU Main Campus"), and prevents logging.
   - Forgotten Clock-Out: Attendance logs are tracked on a per-calendar-day basis
     (log_date == today_date). An unclocked previous shift leaves time_out as null
     (flagged as an "Incomplete Punch"), but NEVER blocks the employee from clocking
     in the following morning. Supervisors and HR can reconcile missing departures
     against the employee's timestamped, geotagged DAR photo submission.

UPDATE NOTES: 2026-11-19 (Commit 98b941e)
Polygon Geofence Accuracy Buffer, Progressive GPS Refinement & Mobile Optimization
================================================================================

SUMMARY FOR MOBILE & APP DEVELOPERS
-----------------------------------
1. Polygon Geofencing with Mobile Device Accuracy Buffer:
   - Backend (backend/app/routers/attendance.py & geofence.py) and Frontend
     (src/utils/campusGeofence.js) now support distance-to-polygon validation.
   - Points inside polygon vertices are verified at 0.0m.
   - For points outside the polygon perimeter, a dynamic tolerance buffer is
     evaluated: tolerance = max(50m, min(accuracy, 150m)).
   - This accommodates mobile GPS jitter, indoor concrete attenuation, and
     cellular tower triangulation drift when on campus.
   - Out-of-bounds rejection error messages now report the true perpendicular
     distance to the campus boundary (e.g. "80m away from EVSU Main Campus")
     rather than calculating Euclidean distance to the center coordinate.
   - PunchRequest payload now accepts an optional accuracy parameter (float).

2. Removal of Obsolete Hardcoded Fallback Coordinates:
   - Removed the obsolete development mock coordinates (11.0065, 124.6075) that
     were 494 meters south of EVSU Ormoc Main Campus.
   - Standardized primary campus center across backend/app/config.py, models,
     and frontend to the true campus coordinate: (11.010466, 124.605469).
   - If GPS acquisition fails or times out, the system no longer sends a fake
     location 494m away; it clearly notifies the employee to enable device GPS.

3. Progressive High-Accuracy GPS Acquisition & Live UI Status:
   - Replaced single-shot getCurrentPosition with navigator.geolocation.watchPosition
     with enableHighAccuracy: true and an 8-second satellite lock window.
   - Auto-locks immediately when satellite precision achieves <= 25 meters.
   - Added a real-time GPS Status Bar in the Employee Attendance dashboard showing
     live satellite accuracy (e.g. "Live GPS Ready (±12m)") and a manual
     "Refresh GPS" action button.

UPDATE NOTES: 2026-11-15 (Commit 836ad1a)
Cloud Deployment, Brevo REST Email Delivery & Auth Flow Hardening
================================================================================

SUMMARY FOR MOBILE & APP DEVELOPERS
-----------------------------------
1. Live Cloud Backend API is now available:
   - Base API URL: https://performacos-api.onrender.com/api
   - Live Health Check: https://performacos-api.onrender.com/api/health
   - Web App URL: https://performacos.onrender.com
   - Mobile app developers can target the live cloud API directly:
     * Production: https://performacos-api.onrender.com/api
     * Local Dev (Android Emulator): http://10.0.2.2:8000/api
     * Local Dev (iOS Simulator): http://localhost:8000/api
     * Local Dev (Physical Device via LAN): http://<host-ip>:8000/api

2. Production Outbound Email Delivery (Brevo HTTPS REST API):
   - Background: Cloud hosting firewalls (e.g. Render Free Tier) drop outbound
     TCP traffic to standard SMTP ports (25, 465, 587).
   - Solution: Integrated Brevo's HTTPS REST API (Port 443) via direct POST to
     https://api.brevo.com/v3/smtp/email.
   - Capability: Sends transactional emails (OTPs, invitations, welcome notes)
     to ANY recipient domain worldwide without domain DNS locking (verified for
     both @evsu.edu.ph institutional emails and @gmail.com personal accounts).
   - Real-Time Debugging: In addition to sending email, all generated OTPs are
     echoed to backend stdout ([AUTH OTP] Generated OTP ...) so you can inspect
     the live server logs during app development if needed.

3. Authentication & Password Recovery Endpoints:
   - POST /api/auth/forgot-password:
     * Request body: {"email": "user@evsu.edu.ph"}
     * Response: {"message": "If that email is registered, an OTP has been sent."}
     * Behavior: Generates a randomized 6-digit numeric OTP code valid for 10
       minutes, marks old OTPs for that user as used, and dispatches email.
   - POST /api/auth/verify-otp:
     * Request body: {"email": "user@evsu.edu.ph", "otp_code": "123456"}
     * Response: {"valid": true, "reset_token": "<jwt-reset-token>"}
     * Behavior: Validates active OTP and returns single-use password reset token.
   - POST /api/auth/reset-password:
     * Request body: {"reset_token": "<jwt-reset-token>", "new_password": "..."}
     * Response: {"message": "Password reset successful."}
     * Password Rule: Unified to minimum 8+ characters (with at least 1 uppercase,
       1 lowercase, 1 digit, and 1 special symbol).

4. Frontend & Mobile UI State Hardening:
   - Password Recovery Button Unfreeze: Fixed an issue where the OTP submit button
     remained stuck on "Validating..." if an invalid code was entered. The state
     now catches errors and immediately resets loading state to re-enable inputs.
   - Independent Password Visibility Toggles: "New Password" and "Confirm New
     Password" fields now have separate show/hide eye buttons.
   - Password Requirements: Standardized on 8+ characters across the app.

5. Cloud Infrastructure & Security:
   - Containerization: Added backend/Dockerfile (Python 3.11-slim, unprivileged
     appuser UID 1000, dynamic $PORT binding).
   - Security Headers: Added FastAPI middleware enforcing X-Frame-Options: DENY,
     X-Content-Type-Options: nosniff, X-XSS-Protection: 1, and Referrer-Policy.
   - Flexible CORS: CORS_ORIGINS parser in backend/app/config.py supports both
     comma-separated strings and JSON arrays.
   - Single Page App Routing: Added public/_redirects (/* /index.html 200) for
     clean client-side routing on CDN.
   - Database Version: Supabase PostgreSQL alembic_version stamped to head
     revision '050f6cfc45be' with all 16 tables synchronized.

UPDATE NOTES: 2026-11-10 (Commit db331f5 / Baseline 6915a27)
Invitation Link HTTPS & Same-Browser Routing, Role Scoping & Manual User Creation
================================================================================

SUMMARY OF CHANGES
------------------
This update fixes invitation link loading issues, enforces strict role and
department scoping for onboarding, and restores full-featured manual account
creation inside User Management.

1. Invitation Link HTTPS & Same-Browser Routing Fixes
------------------------------------------------------
- Problem Fixed:
  - Previously, backend invitation links defaulted to http://localhost:5173,
    causing Chrome ERR_EMPTY_RESPONSE because Vite dev server runs on HTTPS
    (@vitejs/plugin-basic-ssl).
  - Opening an invitation URL (?token=...) in a browser that already had an
    active logged-in session in localStorage skipped the signup screen and
    redirected to #/dashboard.
- Changes:
  - backend/app/config.py:
    * Updated default APP_FRONTEND_URL from "http://localhost:5173" to
      "https://localhost:5173".
    * Added "https://localhost:5173" and "https://127.0.0.1:5173" to default
      CORS_ORIGINS.
    * Added Settings.frontend_base_url helper to strip trailing slashes cleanly.
  - backend/app/email_service.py & backend/app/routers/invitations.py:
    * Switched all email/invitation URL builders to use settings.frontend_base_url.
    * Trimmed whitespace on incoming token in GET /api/invitations/validate.
  - src/App.jsx:
    * Ensured ?token=... and ?invite=... URLs always open TokenizedSignUp even
      when a previous user session is present in localStorage.
    * Preserved query token during signup and cleared stale cache/session state
      when completing registration or returning to login.
  - src/components/auth/TokenizedSignUp.jsx:
    * Included departmentId in registered user state passed into handleLogin.

2. Invite Modal Scoping & HRMDO Office Locking
----------------------------------------------
- Changes:
  - src/components/management/UserManagement.jsx &

    * On the University Departments tab ("+ Invite Personnel" and department-level
      invite buttons), the Account Role selector now only allows "COS Employee"
